# Part 2: the exit plan's runner

## Why

Vendor skill pack 32.0.94 (exported at 170.0.0) states four exit-plan rules that v0.14.0 did not model:

1. What a plan does not close is the **runner**. Only Trailing exits it, so a plan that leaves one is refused while
   `trailingEnabled` is false.
2. A plan's risk-reward is **share-weighted**: each share at its target, and the runner at the last target that closes
   a share. v0.14.0's `plan_pays` was `sum(m * pct) / sum(pct)` over the closing legs. The two disagree whenever a plan
   leaves a runner after two different R legs.
3. A last target closing 0% is the **trail objective**. It sets how far the runner's trail measures and earns no reward.
4. Raising `minRiskRewardRatio` above an all-R plan's risk-reward is refused until that plan changes.

v0.14.0's 32 probes could not tell rule 2 from its own formula. Every one of them staged `trailingEnabled` true (plan
72's request), and the only plan where the two readings differ is X3: 2.0625 vs 2.25, both above the 1.5 minimum.

## What was measured

What the answers settle, rule by rule:

1. **Runner and Trailing: measured.** A runner with Trailing off is a draft error on the plan (T1, T2), and a trail
   objective does not change that (T2). Trailing off with no runner is clean (T3), and the same runner with Trailing on
   is clean (T4).
2. **Share-weighted risk-reward: measured.** The stage names 2.4R (W1) and 1.5R (O1). The previews read 2.25, 2.4 and
   1.6 beside every stop, the same for each stop, as an all-R plan should be. Two plans that v0.14.0 would have refused
   stage clean (W2b, W3).
3. **Trail objective: measured.** It earns nothing (O1 pays 1.5, not 2.7) and sets the runner's trail: O4's trail
   reads 2.7R where W3's, with no objective, reads 0.99R at stops ATR 1.5 and 2. The trail read the plan's farthest
   target times 0.45, the base plan's `trailingGivebackPct` 45 (6 x 0.45, 3 x 0.45, 2.2 x 0.45), except W3 at stop
   ATR 1, which read `runnerTrail` {atrMultiple 1, rMultiple 1}: 1.0R, not 0.99, apparently a one-ATR floor. Only one
   giveback was sent, so the relation is recorded, not modelled. omega computes no trail.
4. **Raising the minimum: on a CREATE, this is rule 2's refusal** (W1, O1). The UPDATE form, a stage that raises only
   the dial under a live plan, was not sent.

Two rules the pack also states came up while probing, and were measured: the share minimums (S1, S2) and the 0% leg's
placement (O2, O3). W2 surfaced a step the schema does not publish: `minRiskRewardRatio` must be a multiple of 0.25.

## Where OMEGA holds it

| Rule | Code |
| --- | --- |
| what a plan pays | `omega/trade_levels.py` `plan_pays`: `(sum(m * pct over closing legs) + runner * m(last closing leg)) / 100`; a 0% leg earns nothing. The rule compares `plan_pays_exact` (each number read as the decimal it was written as, `Fraction(str(x))`), so a plan paying exactly the minimum is not refused: in binary floats 0.6R 50 + 1.4R 28 paid 0.9999999999999999 against 1 and 0.6R 50 + 1.9R 9 paid 1.2499999999999998 against 1.25. `plan_pays` returns the float for display. `plan_pays_v0_14_0` keeps the old reading for comparison only |
| a runner while Trailing is off | `TRADE_MENU_EXIT_PLAN_RUNNER_WITHOUT_TRAILING` on `tradeLevelMenu.<side>.exitPlans[i]`. `validate_menu(..., trailing_enabled=)` takes the POSITION_MANAGEMENT value; `None` (not known) warns `TRADE_MENU_EXIT_PLAN_RUNNER_TRAILING_UNKNOWN` on each plan that leaves a runner instead of passing it |
| a 0% leg after legs closing 100% | `TRADE_MENU_EXIT_PLAN_ZERO_WITHOUT_RUNNER` on `targets[i].closePct` |
| a 0% leg that is not the last | `TRADE_MENU_EXIT_PLAN_ZERO_NOT_LAST` on `targets[i].closePct`. A 0% first leg stays `..._FIRST_LEG_EMPTY` alone, as X7 answered |
| a runner of 1 - 4% | `TRADE_MENU_EXIT_PLAN_RUNNER_UNDER_5` on `targets` |
| a leg closing 1 - 4% | `TRADE_MENU_EXIT_PLAN_LEG_UNDER_5` on `targets[i].closePct` |
| the 0.25 step | `omega/execution.py` `ENFORCED_STEPS`, `validate_execution`: `EXECUTION_OFF_STEP` on `execution.minRiskRewardRatio`. An UPDATE restaging TRADE_LEVEL_POLICY carries the live value as read: `update_menu_findings` warns `EXECUTION_CARRIED_OFF_STEP` on `TRADE_LEVEL_POLICY.minRiskRewardRatio` when that value is off its step (the stage's answer on an UPDATE is unmeasured) |
| the plan's own Trailing | `omega/generate.py`: `menu_findings` passes the plan's effective `trailingEnabled`. `update_menu_findings` passes the update's POSITION_MANAGEMENT, else the strategy's current one. A live runner under an update that only switches Trailing off is a warning, because the update form is unmeasured |

`tests/test_exit_plan_runner_171.py` replays all 14 probes on the field the platform named. It also checks `plan_pays`
against each "pays XR" refusal and against every rendered preview's `riskRewardRatio`, setup by setup. Every v0.14.0
replay (`tests/test_exit_plans_170.py`, 32 probes, and the Y-series pays) stays green unchanged.
